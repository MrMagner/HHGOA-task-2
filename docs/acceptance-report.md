## Validated Pipeline Latencies (Actual Measured Values)

| Stage | P50 | P70 | P90 | P95 | P100 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Embedding | 19.63 ms | 21.35 ms | 30.68 ms | 38.74 ms | 69.35 ms |
| Retrieval | 4.96 ms | 5.30 ms | 5.98 ms | 6.43 ms | 7.93 ms |
| Guardrails | 0.13 ms | 0.15 ms | 0.17 ms | 0.18 ms | 0.21 ms |
| **Total (text, local)** | **25.09 ms** | **26.90 ms** | **36.39 ms** | **44.97 ms** | **75.63 ms** |

> **Note:** The "generation" column in the benchmark was 0.11–0.44 ms because the benchmark used DEMO mode for LLM (no network). Real Groq generation adds ~2000 ms.

### Real Network Latencies (Single Voice Query, Browser-Verified)

| Stage | Measured Value |
| :--- | :--- |
| Sarvam STT | ~577 ms |

| Hybrid Retrieval | ~6.5 ms |

| Guardrails | ~0.45 ms |
| **Total Voice (browser)** | **~10,230 ms (cold) / ~2,800 ms (warm)** |

### Browser-Observed Total Latency

The user-observed browser voice test completed in approximately **11.9 seconds** total (including cold model load). On warm requests, the total is approximately **2,800 ms** dominated by STT (~577 ms) and LLM generation (~2177 ms).

> **IMPORTANT:** This system does NOT achieve <200 ms end-to-end voice latency. The <200 ms figure applies ONLY to local retrieval + guardrails (no network). Full voice RAG requires STT and LLM network calls that add ~2,700 ms minimum.

## No Fabricated Data

- All latency values above were measured from actual API calls and benchmark runs.
- The 100-query benchmark used real MSMARCO-XI vectors (not synthetic data).
- The voice test used a real Hindi audio file transcribed by real Sarvam API.
- The LLM answer was generated by real Groq API using retrieved Hindi context.
